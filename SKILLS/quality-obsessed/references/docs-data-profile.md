# Docs And Data Profile

Use for documentation, specs, reports, analysis, datasets, dashboards, and read-only audits.

## Documentation and specs

Inspect reader's task, decision, next action, examples, constraints, acceptance criteria, caveats, and nearby contradictions. Documentation-only changes count when the contract is more accurate, actionable, or verifiable.

Cross-check commands, flags, APIs, paths, and current claims against primary or repository-owned sources. Render or convert when layout is part of claim.

## Data and reports

Start from decision or question the artifact must support. Check metric definitions, source lineage, data quality, missingness, filters, time windows, denominators, and caveats before polishing presentation.

Separate observed facts, calculations, interpretation, and recommendation. Expected values: worked example, agreed definition, query result, fixture, or independent source.

## Audit mode

Audit requested surface without changing the target. Findings: location, evidence, user or operator harm, likely cause, severity, recommended move, proof needed. Open findings affect the artifact verdict; do not block a completed audit.

## Proof

Exact source pointers, rendered output, validation commands, query results, reconciled totals, or before/after reader tasks. If current or external facts shape the conclusion, cite primary source and identify uncertainty.
